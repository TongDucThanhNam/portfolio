# Better-T-Stack Cloudflare Architecture

## Stack Shape

This repo is aligned to the Better-T-Stack generator shape:

```sh
npx create-better-t-stack@latest tanstack-start-portfolio \
  --frontend tanstack-start \
  --backend self \
  --runtime none \
  --database sqlite \
  --orm drizzle \
  --api none \
  --auth none \
  --payments none \
  --addons turborepo biome \
  --examples none \
  --db-setup d1 \
  --manual-db \
  --web-deploy cloudflare \
  --server-deploy none \
  --no-git \
  --package-manager npm \
  --no-install
```

## Boundaries

- `apps/web` owns the TanStack Start app, Vite config, public assets, routes, and UI.
- `packages/infra` owns Alchemy resources: TanStack Start Cloudflare app and D1 database.
- `packages/db` owns Drizzle schema and generated D1 migrations.
- `packages/env` owns typed `cloudflare:workers` access and the local development shim.
- Root `package.json` only orchestrates workspace commands.

## Runtime Path

```txt
HTTP request
  -> Cloudflare Worker generated by Alchemy TanStackStart
  -> TanStack Start server/runtime
  -> route code in apps/web
  -> optional server code imports packages/db
  -> packages/db reads env.DB from cloudflare:workers
  -> Cloudflare D1 binding
```

## Local Dev Path

```txt
npm run dev
  -> apps/web Vite dev server
  -> vite.config.ts checks for .alchemy/local/wrangler.jsonc
  -> if absent, aliases cloudflare:workers to packages/env/src/cloudflare-local.ts
  -> browser-heavy home route remains ssr: false
```

## Deploy Path

```txt
npm run deploy
  -> packages/infra alchemy deploy
  -> D1Database("database")
  -> TanStackStart("web", cwd: "../../apps/web")
  -> DB binding injected into Worker env
```

## Notes

- D1 is SQLite-compatible from the app's perspective, so `bts.jsonc` records `"database": "sqlite"` and `"dbSetup": "d1"`.
- `drizzle-orm` is also present at root because npm workspaces otherwise place it under `packages/db/node_modules`, while Drizzle Kit resolves the ESM peer from root.
- Docker was removed from the primary deploy path because it conflicts with the Cloudflare Worker target.
